# Claude Code 0.1.9 빈 요청 영수증 검증 — 2026-10-04

0.1.8에서는 추가 능력을 사용하지 않은 요청의 최종 답변에 영수증이 빠질 수 있었습니다. 0.1.9는 프롬프트 훅이 확인한 빈 기록을 모델에 전달해, 일반 요청에서도 추가 도구 호출 없이 0개 영수증을 표시하도록 수정했습니다. 실제 설치본으로 빈 카탈로그와 정적 스킬 사용 흐름을 각각 확인했습니다.

## 누락 원인과 수정

최근 실제 Claude 세션은 시작·프롬프트 관찰 이벤트가 있었지만 관리자 도구 호출과 최종 영수증 표시가 없었습니다. 기존 SessionStart 안내는 능력을 사용한 뒤 release를 호출하도록 했고, 포함 스킬의 상세 안내는 능력 부족이 있을 때만 읽혔습니다. 일반 요청은 두 조건을 모두 지나칠 수 있었습니다.

- SessionStart는 능력 사용 여부와 관계없이 완료한 요청의 끝에 영수증을 표시하도록 안내합니다.
- UserPromptSubmit는 실제 준비 기록과 정리 오류가 모두 없는 경우에만 확인된 빈 영수증을 제공합니다. 이후 준비·재활성화를 시도하지 않았다면 이 영수증을 그대로 표시합니다.
- 준비를 시도했거나 기존 기록이 있으면 마지막 능력 사용 뒤 명시적 release의 최신 영수증을 사용합니다. 확인할 수 없는 상태를 0개나 정리 성공으로 추정하지 않습니다.
- 빈 영수증과 상세표 모두 추가 설치·캐시 재사용·권한 해제·활성 권한 수를 표시합니다.

SessionEnd는 정리와 파일 저장을 반복하는 보완 경로입니다. Claude는 이 훅의 JSON 출력을 최종 대화에 표시하지 않으므로, 종료 훅만으로 답변 끝에 표를 붙일 수 없습니다. [Claude 훅 문서](https://code.claude.com/docs/en/hooks).

## 최종 설치본 검증 조건

- Claude Code `2.1.282`, 사용자 범위에 설치·활성화된 관리자 `0.1.9`.
- 구현 커밋 `03dfcd24fa82e3413f6a20b54dc53c3775c9b5d7`을 main에 푸시하고 표준 `claude plugin update`로 실제 설치본을 갱신했습니다. 코드·훅·스킬·스크립트·매니페스트 33개 파일의 SHA-256이 소스와 일치했고, Claude 매니페스트의 엄격 검증도 통과했습니다.
- 최종 두 실행은 `--plugin-dir`, 임시 MCP 등록, 재연결 제어 요청 없이 설치본을 자동 로드한 독립 UUID 새 세션입니다.
- 합성 카탈로그·정책·DB·작업 폴더를 사용했습니다. 실사용 DB에 평가 기록을 섞지 않았으며 증거 추출 후 임시 DB·준비한 스킬 캐시·작업 폴더를 삭제했습니다.
- 권한 모드는 `manual`, 비대화형 승인 응답은 `none`, 기본 도구는 `Skill,ToolSearch`였습니다. 빈 요청에는 `--allowedTools`도 지정하지 않았습니다.
- 스킬 사용 요청에만 관리자 도구 6개, 포함 스킬의 정확한 이름, ToolSearch를 해당 실행에 좁게 허용했습니다. 영구 승인 설정이나 신뢰 기록을 변경하지 않았습니다.
- 두 사용자 프롬프트 모두 영수증이나 표 표시를 요청하지 않았습니다.

## 검증 중 연결 실패와 복구

최종 성공 이전의 실패도 성공률에서 제외하지 않고 별도로 보존했습니다.

| 단계 | 결과 |
| --- | --- |
| 소스 0.1.9 빈 요청 | 13개 도구 로딩, 자동 0개 표시 성공 |
| 소스 0.1.9 스킬 사용 3회 | MCP 연결 실패, 스킬 적용 미완료 |
| 설치본 0.1.8 비교 실행 | 스킬 적용·해제·표시 성공 |
| 설치본 0.1.9 초기 빈 요청 | 0개 표시는 성공했지만 MCP 연결 실패 |
| 설치본 0.1.9 초기 스킬 사용 2회 | MCP 연결 실패, 스킬 적용 미완료 |
| 설치본 0.1.9 서버 직접 실행 / claude mcp get | 정상 응답, 도구 13개 / connected |
| 공식 SDK 재연결 제어 | failed → connected, 도구 13개 |
| 이후 설치본 0.1.9 새 세션 2회 | 위 최종 표의 두 흐름 성공 |

첫 소스 스킬 사용 실패에서는 `CONNECTION_CLOSED`를 관찰했습니다. 후속 실패의 ToolSearch 결과와 네이티브 SDK 상태 조회에는 이전 실패를 15분 동안 캐시해 연결을 건너뛴다는 메시지가 있었습니다. 이 단계의 로그에는 관리자 서버 시작 시도도 없었습니다. 따라서 이 후속 결과만으로 0.1.9의 서버 코드나 패키지 경로가 고장났다고 판단할 수 없습니다. 최초 연결 종료의 근본 원인은 이번 자료로 확정하지 못했습니다.

설정·설치 캐시·승인 기록을 직접 편집하지 않고 Claude가 지원하는 `reconnect_mcp_server`에 해당하는 네이티브 제어 요청으로 이 로컬 서버만 재연결했습니다. 모델 요청 없이 연결을 복구했고, 실패 캐시 항목이 제거됐음을 확인했습니다. 이후 새 대화에서는 별도 재연결 없이 정상 로드됐습니다. 이 진단 중에는 환경 변수로 기존 claude.ai 커넥터 자동 연결을 껐고, 평소 설정은 변경하지 않았습니다. [Claude SDK 재연결 문서](https://code.claude.com/docs/en/agent-sdk/python).

연결 실패 사례의 CLI 결과 subtype이 success라도 요구한 스킬 적용은 실패입니다. 관리자 도구 등록 수와 호출 결과, 지침 표식, 실제 영수증을 함께 확인했습니다. 이 기능이 네이티브 MCP 연결 실패를 자동 복구한다는 의미는 아닙니다.

## 검증 범위와 설치·정리 내역

- 전체 기능 테스트 66개가 통과했습니다. 후보가 있는 일반 요청의 확인된 빈 영수증과, 준비한 이후 이전 빈 영수증을 다시 제공하지 않는 회귀 검증을 포함합니다.
- 기존 SKILL.md의 단순 name·description frontmatter는 그대로 유지했습니다. skill-creator의 별도 quick_validate.py는 검증 환경의 PyYAML 부재로 실행하지 못했습니다. 이 검증을 위해 의존성을 설치하지 않았고, frontmatter 확인·Claude 엄격 매니페스트 검증·실제 스킬 읽기와 적용을 따로 확인했습니다.
- 관리자 Claude 플러그인만 0.1.8에서 0.1.9로 업데이트해 유지했습니다. 새 외부 플러그인·커넥터·OAuth 계정 연결, 네이티브 제거는 없었습니다. 기존 커넥터 도구도 호출하지 않았습니다.
- 이번 비교 실행과 최종 성공 실행에서 검증용 정적 스킬을 각각 1개 준비했습니다. 두 임시 스킬의 세션 권한을 해제하고 증거 추출 후 각 캐시를 삭제했습니다.
- 이미 실행 중인 Claude 프로세스에는 예전 플러그인이 로드될 수 있습니다. 업데이트된 안내를 적용하려면 새 Claude 프로세스로 시작해야 합니다.
- Codex 설치본과 사용자가 신뢰한 사용자 훅은 기존 0.1.8로 유지했습니다. 이번 검증은 Claude의 표시 문제를 대상으로 합니다.

표시 수치는 관리자를 통해 추가한 능력의 기록입니다. 컴퓨터에 이미 설치된 모든 네이티브 스킬·플러그인의 전체 개수나 네이티브 제거 기록을 관찰하는 기능은 아닙니다. 해제는 세션 임시 권한 종료이며 패키지 캐시 삭제와 구분합니다. 두 합성 요청의 성공으로 모든 작업에서 표시가 보장되거나 판단 정확도·시간 절감 효과가 입증됐다고 일반화하지 않습니다.
