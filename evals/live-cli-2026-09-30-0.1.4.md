# Codex CLI 0.1.4 실환경 확인

합성 메모만 사용한 새 `codex exec --ephemeral --json` 세션을 읽기 전용으로 실행했다. 관리자 플러그인은 `0.1.4`로 다시 설치했고 사용자 훅 세 개가 동작했다.

| 사례 | 훅 후보 | 관리자 도구 호출 | 활성화 | 해석 |
| --- | --- | --- | --- | --- |
| 스킬을 명시한 회의록 요청 | `note-summarizer` | `resolve_capability` 시도 | 없음 | 비대화형 CLI의 승인 정책이 MCP 호출을 거부함 |
| 팀 양식을 암시한 회의록 요청 | `note-summarizer` | `resolve_capability` 시도 후 `search_capabilities` 성공 | 없음 | 활성화 호출은 승인 거부, 읽기 탐색은 성공함 |
| 단순 문장 요약 | 없음 | 없음 | 없음 | 추가 능력을 시도하지 않음 |

도구 호출 이벤트는 모델이 실제로 탐색을 시도했음을 보여준다. `resolve_capability` 거부는 필요성 판단 실패와 구분한다. 격리용 `CAPMGR_DATA_DIR`가 훅에는 전달되지만 MCP 서버에는 전달되지 않아, 두 상태 DB의 같은 턴 판단 공유와 종료 해제는 이 실험으로 확인할 수 없었다. 이 구간은 테스트에서 훅·MCP 프로토콜과 정책 경로를 각각 확인했다.

CLI 자동 승인 옵션을 더해 전체 활성화를 재검증하려는 실행은 자동 승인 검토가 거절했다. 읽기 전용 실험 결과만 남기고 해당 옵션은 검증기에서 제거했다. 실제 Claude Code CLI는 설치되어 있지 않아 검증하지 못했다.
