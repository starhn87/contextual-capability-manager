# Codex 설치만으로 실행하기 위한 신뢰 경계 조사 — 2026-10-04

일반 플러그인이 설치 과정에서 자기 훅을 자동 신뢰시키는 공식 경로는 확인되지 않았습니다. 현재 설치된 Codex CLI `0.159.0`과 공식 문서 기준입니다. 사용자에게 별도 훅 신뢰 조작을 요구하지 않으려면 핵심 기능을 MCP·스킬로 초기화하고 훅을 선택 기능으로 만드는 설계가 적합합니다. 이 문서는 조사와 개선안이며, 아래 구조 변경은 아직 구현되지 않았습니다.

## 공식 지원 범위

일반 플러그인의 훅은 설치·활성화와 별도로 정의를 검토·신뢰해야 합니다. 신뢰는 현재 정의의 해시에 연결되고 변경된 정의는 다시 검토 대상이 됩니다. 명령 훅을 MCP 도구 훅으로 바꿔도 같은 신뢰 절차가 적용됩니다. [Codex 훅 문서](https://learn.chatgpt.com/docs/hooks), [플러그인 패키징 문서](https://developers.openai.com/plugins/build/plugins).

| 경로 | 사용자별 훅 신뢰 조작 생략 | 일반 설치 흐름에 적용할 수 있는가 |
| --- | --- | --- |
| 일반 플러그인 설치·활성화 | 아니오 | 현재 설치만으로 훅 자동 실행은 보장되지 않음 |
| 관리자 정책의 managed 훅 | 가능 | 기업 관리자가 정책과 스크립트를 별도로 배포하는 환경에 해당 |
| `--dangerously-bypass-hook-trust` | 해당 CLI 실행에서 가능 | 외부에서 출처를 검토한 단발 자동화용이며 보통의 새 데스크톱 채팅에 적용되지 않음 |
| 훅 없이 MCP·스킬을 기본 경로로 사용 | 훅 신뢰 자체가 필요 없음 | 핵심 기능의 세션 초기화·정리를 MCP 쪽으로 옮기는 구현이 필요 |

관리자 훅은 시스템·MDM·관리 정책으로 신뢰됩니다. 플러그인을 설치하는 것만으로 관리자 배포가 되지는 않으며, 관리 디렉터리의 스크립트도 별도로 전달해야 합니다. [관리형 설정 문서](https://learn.chatgpt.com/docs/enterprise/managed-configuration).

단발 CLI 옵션은 영구 신뢰 등록을 만들지 않습니다. 이 조사에서는 사용하지 않았고 신뢰 기록이나 관리자 정책을 수정하지 않았습니다. [Codex 훅 문서](https://learn.chatgpt.com/docs/hooks).

## 로컬 런타임에서 확인한 사실

| 확인 대상 | 관찰 결과 |
| --- | --- |
| `codex plugin add --help` | 설치와 훅 신뢰를 합치는 옵션 없음 |
| `codex --help` | 해당 실행의 훅 신뢰 우회 옵션은 있음 |
| 실험 필드까지 포함한 app-server `ClientRequest` 스키마 | 훅 요청 메서드는 `hooks/list`만 확인됨. 전용 신뢰 부여 API 없음 |
| 훅 관련 스키마 파일 | `HooksListParams`, `HooksListResponse`, `HookStartedNotification`, `HookCompletedNotification` |
| 훅 상태 enum | `managed`, `trusted`, `untrusted`, `modified` |
| 설치된 관리자 MCP | 도구 13개 로드 확인 |
| 패키지에 포함된 훅 | 이 환경에서 목록에 나타나지 않음 |
| 이전 검증에서 등록한 사용자 훅 3개 | 활성 설정이지만 `untrusted` |

패키지 훅의 발견 여부와 발견된 훅의 신뢰 여부는 별개입니다. manifest의 경로는 문서 형식에 맞지만 현재 런타임에서 패키지 훅을 발견하지 못했습니다. 발견 문제를 수정하더라도 일반 플러그인 훅의 신뢰 요구는 남습니다. 내부 신뢰 저장소를 직접 편집하는 방식을 지원 API로 해석하지 않습니다.

## 현재 0.1.8의 의존성과 개선안

현재 MCP 도구는 세션 ID를 받고 스킬 안내는 SessionStart가 이를 프로젝트 맥락에 연결한다고 설명합니다. `initialize`는 프로토콜 정보만 반환하며 세션을 만들지 않습니다. MCP 프로세스 종료는 게이트웨이 연결을 닫지만 모든 활성 lease의 해제와 요약 저장을 보장하지 않습니다. 따라서 훅 파일만 빼면 설치만으로 동작하는 제품이 완성되는 것은 아닙니다.

다음 구조를 권장합니다.

1. MCP에 세션 시작 도구를 추가해 불투명한 관리자 세션 핸들과 저장소 ID를 반환합니다. 스킬은 추가 능력이 필요해진 첫 호출에서 자동으로 이를 받습니다. 네이티브 채팅 ID를 얻지 못할 때 임의 값을 네이티브 ID라고 표시하지 않습니다.
2. 모든 후속 호출은 반환받은 핸들과 저장소 ID를 사용합니다. 한 MCP 프로세스가 여러 채팅을 처리할 가능성을 고려해 프로세스 ID를 채팅 ID로 사용하지 않습니다. 재연결·세션 복구와 여러 채팅의 권한 격리 규칙도 함께 정합니다.
3. 정적 스킬의 탐색·지침 적용·결과 기록·최종 요약표는 MCP와 포함 스킬 안내로 완료합니다. 최종 답변 전에 명시적 release를 호출합니다.
4. 정상 MCP 연결 종료 시 해당 연결이 소유한 세션만 정리합니다. 강제 종료에는 lease 만료를 보조 수단으로 유지하고, 해제·캐시 보관·실제 삭제를 요약에서 구분합니다.
5. 훅은 전체 프롬프트 관찰과 네이티브 종료 이벤트의 보조 정리 기능으로 남깁니다. 훅이 없을 때 수집하지 못한 프롬프트를 관찰한 것으로 계산하지 않습니다.

이 설계는 훅 신뢰 요구가 핵심 기능을 막지 않게 합니다. 모델의 스킬 선택과 도구 호출에 의존하므로 모든 프롬프트의 자동 관찰이나 최종 답변의 요약표를 무조건 보장하는 경로는 아닙니다. 현재 MCP의 자동 로딩 관찰에서 도출한 개선안이며 훅 없는 Codex 실제 대화 검증은 아직 완료되지 않았습니다.

## 구현 완료를 판단할 기준

- 훅이 없거나 전부 `untrusted`인 새 Codex 채팅에서 사용자 설정 편집 없이 관리자 세션을 생성하고 정적 스킬을 적용한다.
- 최종 답변에 준비·사용 결과·권한 해제·캐시 상태를 표시하고, 저장된 요약과 일치한다.
- 다른 채팅의 lease를 해제하지 않으며 MCP 재연결과 이중 release도 처리한다.
- 정상 연결 종료와 강제 종료의 정리 범위를 구분해 검사한다.
- 훅 없는 실행의 관찰 범위를 지표에 표시하고 네이티브 채팅 ID·프롬프트 관찰·정리 성공을 만들지 않는다.

플랫폼의 도구 승인과 외부 계정 인증은 별도입니다. Codex는 사용자 설정에서 플러그인별 MCP 도구 승인 정책을 조정할 수 있지만 이를 훅 자동 신뢰로 해석할 수 없습니다. [플러그인 패키징 문서](https://developers.openai.com/plugins/build/plugins). 로그인 후 Claude의 전체 흐름은 해당 실행에 도구를 좁게 허용한 조건에서 성공했으며, 무승인 비대화형 실행에서는 별도 도구 승인 거부를 관찰했습니다.
