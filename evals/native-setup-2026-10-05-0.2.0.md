# 네이티브 설치·인증·작업 재개 검증 — 0.2.0

2026-10-05 소스와 생성된 로컬 패키지를 검증했다. 기존 설치본에 업데이트하거나 원격 저장소로 푸시하지 않았다.

## 검증 결과

- `python3 -m unittest discover -s tests -q`: **119개 통과**. 기존 99개와 새 네이티브/OAuth 경로 20개를 포함한다.
- 격리된 CLI 실행 파일과 실제 loopback HTTP OAuth/MCP 서버를 사용해 설치 명령 실행 → 설치 목록 재확인 → PKCE 등록·콜백·토큰 교환 → 도구 전체 페이지 조회 → 읽기 호출 → 결과 보고 → 권한·토큰 정리를 확인했다. 실제 사용자 네이티브 설치·계정 인증을 수행한 테스트는 아니다.
- 취소·잘못된 상태값·발급자 불일치·콜백 재전송·권한 확대·인증 만료·다른 세션 접근·저장소 불일치·호스트 비활성화·정책 철회·설정 변경·미확인 설치·도구 없음·리디렉션 차단을 확인했다. 토큰이 거절될 때 설치를 재실행하지 않고 인증을 재개하는 경로도 확인했다.
- SQLite·이벤트·저장된 영수증에 인증 토큰과 로그인 URL이 포함되지 않는 것을 검사했다. 원격 도구가 토큰을 응답에 반사할 때도 모델에 전달하기 전에 가린다.
- 실제 Codex CLI의 등록 목록 **5,451개**를 읽어 영어 Linear 연결 요청을 검색했다. `codex-openai-curated-remote-linear`만 후보로 남았으며 추가 설치는 **0개**였다. 이전에 일반 단어가 겹쳐 추천됐던 다른 서비스가 선택되지 않는다.
- 공식 Linear의 경로별 OAuth 리소스 메타데이터와 발급자 메타데이터를 읽어 `/mcp/readonly`, `read`, PKCE S256, 공개 클라이언트 등록 엔드포인트를 확인했다. 실제 Linear 로그인·동의·계정 도구 호출은 아직 검증하지 않았다.
- `python3 scripts/build_marketplace.py`로 생성된 패키지의 공통/Codex/Claude 선언이 모두 **0.2.0**임을 확인했다. 패키지의 실제 stdio MCP 서버를 실행해 초기화 버전, `resume_capability_setup` 노출, 오류 없는 종료를 확인했다.
- `git diff --check`와 Python 컴파일 검사를 통과했다.

## 실제 사용 범위

기본 자동 계정 연결은 Codex의 공식 Linear 플러그인과 관리자 게이트웨이의 공식 Linear 읽기 전용 OAuth MCP이다. Codex 앱의 네이티브 계정 연결 표시가 갱신됐다고 주장하지 않는다. 다른 OAuth MCP는 명시적 연결 설정과 호스트·도구 정책으로 확장할 수 있다. 앱 전용 플러그인에 연결 어댑터가 없으면 설치만 확인하고 `requires_host_activation`을 반환한다.

로그인 후 재개는 지속 실행되는 MCP 서버와 에이전트 지침의 `resume_capability_setup` 대기로 이루어진다. 다른 대화에 메시지를 보내거나 새 에이전트 작업을 생성하지 않는다. 프로세스가 종료되면 메모리 인증은 소멸하므로 새 인증이 필요하다. 네이티브 설치는 세션 해제 이후에도 유지한다.
