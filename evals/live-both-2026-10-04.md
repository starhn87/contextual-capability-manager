### Claude

두 세션 모두 관리자 MCP가 `connected`였고 도구 13개를 로드했습니다. 일반 요청은 도구 호출 없이 다음 영수증을 답변 끝에 표시했습니다.

> 이 세션에서 관리자를 통해 추가한 능력: 없음. 추가 설치 0 · 캐시 재사용 0 · 권한 해제 0 · 활성 권한 0.

스킬 사용은 `Skill → ToolSearch → resolve_static_skill → record_capability_result → release_capability_session` 순서였습니다. `Verification Notes Skill` 1개를 새로 준비했고, 파일에만 둔 `CAPMGR-INSTALLED-SKILL-E2E-20261004` 표식이 답변에 들어갔습니다. 세 관리자 호출의 세션 UUID와 `expected_storage_id`가 훅의 기록과 일치했습니다.

추가 설치 1 · 캐시 재사용 0 · 권한 해제 1 · 활성 권한 0

| 능력 | 종류 | 준비 | 사용 결과 | 세션 권한 | 캐시 |
| --- | --- | --- | --- | --- | --- |
| Verification Notes Skill | 스킬 | 새로 설치 | 성공 보고 | 해제 완료 | 보관 |

위 표는 실제 답변과 release 직후 영수증의 상태입니다. 성공 값은 모델의 보고이며 지침 표식 반영도 별도로 확인했습니다. 이후 검증기가 증거를 추출하고 임시 저장소 전체를 삭제했습니다. CLI 보고 비용은 일반 요청 0.160244 USD, 스킬 사용 요청 0.2475084 USD였습니다. 좁은 실행별 도구 허용을 사용했으므로, 기본 승인 상태에서도 설치·적용이 모두 자동으로 된다는 증거는 아닙니다.

### Codex

일반 요청의 답변은 최대공약수 6만 표시했습니다. 실제 저장소에는 시작·프롬프트 관찰·종료 해제가 기록됐고, 빈 요약 파일도 저장됐지만 대화에 표시되지 않았습니다. 이는 현재 설치본 0.1.8의 결과이며 [0.1.9 표시 수정](live-claude-2026-10-04-0.1.9.md)을 Codex 설치본에서 검증한 결과가 아닙니다.

스킬 사용 요청은 `capability_runtime_status → resolve_static_skill → search_capabilities → release_capability_session`을 호출했습니다. 상태 조회는 같은 네이티브 세션의 연결과 저장소 ID를 확인했고, 읽기 탐색은 기본 후보 `note-summarizer`를 추천했습니다. 저장소 검증 인수가 필요한 세 호출 모두 훅의 저장소 ID와 일치했습니다. 준비와 명시적 해제는 각각 다음 오류로 거부됐습니다.

> MCP tool call requires approval, but approval policy is never

모델은 카탈로그 조회 후 패키지에 이미 포함된 예제 `note-summarizer/SKILL.md`를 파일 읽기로 확인해 회의 내용을 정리했습니다. 관리자 경유 설치·활성화는 수행하지 않았고, 최종 답변에도 영수증을 받지 못했음을 알렸습니다. 로컬 예제 지침 읽기를 관리자가 새 스킬을 설치·전달한 성공으로 계산하지 않습니다.

종료 훅은 모델의 명시적 release 승인 거부와 별개로 실행됐습니다. 종료 후 저장된 영수증의 추가 설치·해제·활성 수는 모두 0이고 정리 오류도 없었습니다. 활성화 자체가 없었으므로 활성 스킬 해제를 성공적으로 검증한 것은 아닙니다. CLI 종료 코드 0은 답변 생성 완료를 뜻하며 요구한 관리자 전체 흐름의 성공을 뜻하지 않습니다.

이번 차단은 비대화형 CLI의 조건입니다. 데스크톱 대화에서 사용자가 도구를 승인했을 때의 결과나 훅 신뢰 문제로 일반화하지 않습니다. 훅 신뢰와 MCP 도구 승인은 별개이며, 공식 문서는 플러그인별 도구 승인 설정을 따로 설명합니다. [Codex 플러그인 문서](https://developers.openai.com/plugins/build/plugins).

## 증거와 정리

실제 모델 실행 4건의 JSONL, 최종 답변, UUID별 DB 기록과 요약을 대조했습니다. 모든 실행의 종료 후 활성 권한과 세션 맥락이 0이고, 정리 오류가 없었습니다. 기존 0.1.9 연결 실패 기록은 [이전 검증 보고서](live-claude-2026-10-04-0.1.9.md)에 그대로 보존했습니다.

Codex 첫 실행 준비에서 임시 MCP 비활성화 옵션이 `invalid transport` 설정 오류를 냈습니다. 모델 세션이 시작되기 전 검증기 오류였고, 해당 옵션을 제거한 뒤 정상 실행했습니다. 실패 기록은 보존하되 모델 실행 4건에는 포함하지 않았습니다.

원시 증거는 저장소 밖 로컬 `both-runtime-verification/report.json` 및 각 실행 폴더에 있습니다. Claude 폴더 이름은 `both-recheck-claude-empty-1`, `both-recheck-claude-skill-1`, Codex는 `codex-installed-empty-2`, `codex-installed-skill-1`입니다. 원시 파일은 이 보고서와 함께 Git에 올리지 않았습니다. Codex 시험 이벤트와 요약은 네이티브 저장소에 남기며 실제 사용자 세션과 섞어 집계하지 않습니다. Claude의 임시 DB·캐시와 두 런타임의 임시 작업 폴더는 삭제했습니다.
