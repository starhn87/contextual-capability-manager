# Codex 훅 없는 정적 지침 조회와 요약 표시 — 0.1.10, 2026-10-04

Codex 설치본 0.1.8에서 재현한 일반 답변의 요약 누락과 정적 스킬 준비 호출의 승인 차단을 보완했습니다. 0.1.10 수정본을 native CLI에 임시 로드했을 때 훅 없이 승인된 로컬 지침을 적용했고, 추가 능력이 없는 답변에도 0개 요약을 표시했습니다. 최종 스킬 반복 실행 두 번은 항목·수치·조회 범위를 포함한 표를 모두 표시했습니다.

이번 결과는 **수정본 소스 검증**입니다. Codex 설치본 0.1.8과 Claude 설치본 0.1.9를 업데이트하지 않았습니다. 사용자 설정·훅 정의·신뢰 기록·전역 도구 승인 정책도 수정하지 않았습니다. 푸시와 설치본 업데이트 후 실제 패키지 검증은 후속 단계입니다. 이전 설치본의 실패는 [비교 보고서](live-both-2026-10-04.md)에 그대로 남겨 둡니다.

위 문단은 소스 검증 시점의 기록입니다. 이후 양쪽 설치본을 0.1.11로 갱신한 결과와 기존 훅 호환성 수정은 [배포·실제 설치본 검증](native-deployment-2026-10-04-0.1.11.md)에 기록했습니다.

## 변경한 동작

기존 `resolve_static_skill`은 지침 조회와 캐시 준비·판단 기록·세션 권한 생성을 함께 처리합니다. Codex의 기본 비대화형 승인 정책에서는 이 호출과 명시적 release가 막혔습니다. 설치를 하지 않아도 읽을 수 있는 지침까지 같은 경로로 처리한 것이 이번 보완 대상입니다.

- Codex의 `read_static_skill`은 현재 정책이 허용한 로컬 또는 기존 캐시의 정적 지침만 선택해 읽습니다. 설치·다운로드·원격 판단·DB 기록·실행·권한 생성을 하지 않으며, 세션 ID나 신뢰된 훅이 필요 없습니다.
- 반환값은 `instructions_ready`와 `scope: read-only-call`입니다. 로컬 지침 읽기는 설치 0개, 기존 캐시 읽기는 캐시 재사용 1개로 구분합니다. 사용 성공·패키지 설치·세션 활성화로 표시하지 않습니다.
- MCP 초기화 안내와 포함 스킬 설명에 요약 표시를 안내합니다. 특히 스킬 선택 전에 보이는 `description`에 일반 답변의 0개 표시를 포함했습니다. 완전한 채팅 이력에서 준비·재활성화와 이전 활성 권한·정리 오류가 없음을 확인할 수 있을 때만 0개를 표시합니다.
- 조회 요약에는 스킬명·지침 출처·추가 권한·캐시 상태와 조회 범위가 들어갑니다. 앞선 준비가 있으면 실제 release와 최신 세션 영수증이 필요합니다. 조회 요약으로 기존 권한을 해제했다고 주장하지 않습니다.
- Claude에서는 새 조회 도구를 노출하지 않고 기존 `resolve_static_skill → record_capability_result → release_capability_session` 경로를 유지합니다. Codex는 관리자 도구 14개, Claude는 13개를 노출합니다.

읽기 전용 주석은 실제로 상태를 변경하지 않는 새 조회에만 부여했습니다. `search_capabilities`는 세션 ID가 있을 때 기록을 쓰고 설정된 원격 판단기를 호출할 수 있어 기존 `readOnlyHint: true`를 바로잡았습니다. 준비·결과 기록·권한 해제 도구를 읽기 전용으로 바꾸지 않았습니다. [공식 MCP 구성 안내](https://developers.openai.com/plugins/build/mcp-server), [공식 도구 주석 지침](https://developers.openai.com/plugins/plugin-guidelines).

## 실패와 보강 과정

실패·변동 실행도 로컬 원본과 집계에서 보존합니다.

1. MCP 초기화 안내만 추가한 일반 요청은 0개 요약을 표시하지 않았습니다. 별도 도구 설명에 안내를 넣어도 같은 결과였습니다.
2. 새 포함 스킬을 프로젝트 경로로 제공해도 기존의 ‘능력이 부족할 때 사용’ 설명만으로는 일반 요청에서 선택되지 않았습니다. Git 작업 폴더를 만든 뒤에도 누락됐습니다. 스킬 선택 설명에 모든 완료 요청의 요약을 명시한 뒤 표시됐습니다.
3. 새 도구를 Claude에도 노출한 초기 호환성 시험은 기존의 좁은 허용 목록에 없는 `read_static_skill`을 선택해 승인 거부가 발생했습니다. Claude 도구 목록에서 제외하고 기존 준비 경로를 안내한 후 성공했습니다.
4. Codex는 지침 적용과 0개 표시가 성공해도 요약표를 숫자 한 줄로 줄인 실행이 있었습니다. 항목 행과 조회 범위를 유지하도록 보강한 최종 두 실행에서는 표가 모두 나왔습니다. 반복 2는 정확한 제목 문자열을 생략했으므로 원본의 제목 검사값은 false이고, 표·수치·조회 범위 검사는 별도로 통과했습니다.

이 결과는 제한된 합성 요청의 동작 검증입니다. 모든 모델·요청에서 동일한 제목이나 표를 무조건 출력한다는 보장은 없습니다. 지연과 토큰 사용량도 전후 조건·반복 실행마다 달라 시간 절감이나 답변 품질 향상을 입증하지 않습니다.

## 남은 범위

미캐시 원격 스킬은 준비와 플랫폼의 정상 승인이 필요합니다. 실행형 플러그인·커넥터와 새 계정 인증도 이번 조회 경로로 자동 처리되지 않습니다. 새 도구의 읽기 전용 주석이 모든 사용자 설정에서 무승인 실행을 보장하지는 않습니다.

읽기 경로는 사용 이벤트를 쓰지 않으므로 기존 효용·판단 통계에 포함되지 않습니다. 전체 프롬프트 관찰, 관리자 세션 핸들, 게이트웨이 연결의 소유 권한 정리와 강제 종료 처리는 [후속 설계](codex-installation-friction-2026-10-04.md)에 남아 있습니다. 포함 스킬과 MCP 안내에 의존하는 요약을 강제 UI 출력으로 바꾼 구현도 없습니다.
