# 배포와 실제 설치본 검증 — 0.1.14, 2026-10-05

Codex와 Claude Code의 관리자 플러그인을 **0.1.14**로 업데이트하고, 실제 설치본을 새 CLI 세션 5건에서 실행했다. 이름을 지정하지 않은 팀 양식 요청에서 양쪽 모두 등록된 지침을 읽고 적용했다. 일반 요청의 추가 설치·재사용·권한 해제·활성 권한 0개 표시도 확인했다. 기존 신뢰 훅을 켠 Codex의 비대화형 CLI에는 불필요한 해제 호출 차단 1건이 남아 있다.

코드 커밋은 `c6f99a3`이다. 목록 자동 탐색·갱신의 [0.1.12 소스 검증](catalog-refresh-2026-10-05-0.1.12.md)에 실제 설치본의 모델 동작 검증을 추가한 결과다. 단위·통합 검사 **99개**, Claude marketplace 검증, 포함 스킬 검증이 통과했다. 양쪽 설치본의 소스 파일 **각 40개**를 빌드·저장소와 SHA-256으로 대조했다.

## 실제 실행 조건

Codex CLI는 `0.159.0`, Claude Code는 `2.1.282`이며 모델 설정을 유지했다. 소스 MCP를 따로 등록하거나 `--plugin-dir`로 덮어쓰지 않았고, 명시적인 관리자 카탈로그·정책도 주입하지 않았다. 시험용 지침은 등록된 로컬 마켓플레이스의 미설치 후보로만 제공했다.

- Codex: 이미 등록된 개발용 로컬 목록에 시험 후보를 임시 추가했다. `codex exec --ephemeral --sandbox read-only`의 기본 비대화형 승인 정책을 유지했다. 훅 없는 실행은 해당 호출에만 `--disable hooks`를 사용했다.
- Claude: 시험용 로컬 마켓플레이스를 native CLI로 임시 등록했다. 관리자 DB·캐시는 별도 임시 디렉터리에 격리했다. `manual`·`--permission-prompts none`을 유지했고, 양식 시험에만 관리자 정적 준비·기록·해제 등 정확한 도구 8개를 좁게 허용했다. 일반 요청에는 이 허용 목록을 사용하지 않았다.
- 프롬프트는 일반 계산과 “우리 팀의 Zebra 릴리스 점검표를 작성해 줘”였으며 스킬·플러그인·커넥터 이름이나 영수증 표시를 요구하지 않았다. 양식 파일에만 둔 표식과 담당자 서연·10월 7일 마감·미정 출시일을 실제 답변과 대조했다.

## 실제 시험에서 보완한 점과 남은 제한

0.1.12의 이름 없는 양식 요청에서 Codex는 후보를 조회하지 않고 일반 표를 작성했다. 0.1.13에서 이름이 있는 팀·프로젝트 양식의 지침이 없으면 작성 전에 조회하도록 스킬과 MCP 안내를 보강했다. 이후 양쪽 새 세션에서 파일 표식을 확인했다.

0.1.13의 Codex 일반 답변은 설치·접근 수치만 간단히 표시하고 기존 네 수치 형식을 생략했다. 0.1.14에서 모든 완료 요청에 영수증을 표시한다는 기존 스킬 선택 조건을 복구했고, 최종 일반 요청에서 네 수치를 확인했다. 새 SessionStart 안내도 실제 준비·재활성화 후에만 해제하도록 명확히 했다.

사용자가 이미 신뢰한 Codex 사용자 훅은 **0.1.8 원본 경로와 코드**를 유지했다. 따라서 이 훅을 켠 최종 CLI 시험에서는 정적 조회 뒤 불필요한 `release_capability_session` 시도가 `approval policy is never`로 차단됐다. 지침 조회·적용은 성공했고 종료 훅 이후 활성 권한과 세션 연결은 모두 0이었다. 이번 결과를 모든 훅·승인 조합에서 경고 없이 동작한다는 증거로 해석하지 않는다. 새 버전의 훅 안내가 기존 0.1.8 신뢰 경로에 적용됐다고 주장하지 않는다.

Claude의 첫 0.1.12 모델 실행은 OAuth 만료로 중단됐다. 사용자의 재로그인 후 최종 실행은 성공했다. 최초 실패와 중간 버전의 표시·선택 누락, 승인 차단은 로컬 원본 기록에 보존했다.

권한 해제와 캐시 삭제는 다른 동작이다. Claude 영수증은 해제 직후 캐시 보관을 표시했고, 이후 시험 harness가 임시 저장소를 제거했다. 일반 제품이 세션마다 모든 패키지를 삭제한다는 의미가 아니다. 원시 CLI 로그·파일 해시·집계 보고서는 로컬 증거로 보관하며 인증 정보와 원시 로그를 Git에 넣지 않았다.

기존 실행 중인 앱·MCP 프로세스의 즉시 재로딩은 검증하지 않았다. 적용된 설치본을 사용하려면 앱·CLI를 재시작하고 새 세션을 열어야 한다. 이번 합성 사례는 목록 전체의 선택 정확도나 실사용 효용을 증명하지 않는다.
