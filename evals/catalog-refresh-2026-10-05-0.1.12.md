# 능력 목록 자동 탐색·갱신 검증 — 2026-10-05

## 변경

- Codex·Claude Code에서 등록된 마켓플레이스를 기본 탐색한다. 명시적인 시험 카탈로그는 플랫폼 목록을 자동으로 섞지 않는다.
- 조회 때 로컬 목록·스킬 파일·정책을 다시 읽고, 실행 중 60초 간격으로 Codex 등록·설치 상태를 재조회한다.
- 등록된 HTTPS Git 목록을 관리자 전용 스냅샷으로 최대 6시간 간격에 갱신한다. 실패하면 마지막 정상 복사본을 유지하고 5분 간격으로 재시도한다.
- 초기 native 조회를 MCP 초기 연결 응답 이후 백그라운드에서 수행한다. 원격 갱신 중에도 정적 조회는 로컬 파일을 사용한다.
- 발견된 native 플러그인·커넥터 참조는 설치·인증을 대신하지 않는다. 기존 native 설치 제한과 사용자 정책을 유지한다.
- 카탈로그가 바뀌어도 사용 중인 능력을 다른 버전으로 바꾸지 않는다. 기존 접근을 해제한 뒤 새 버전을 준비한다.

## 검증 범위

소스 버전 **0.1.12**의 단위·통합 검사와 별도 MCP stdio 프로세스를 검증했다. 실제 등록 목록은 읽었지만 사용자 설치본을 업데이트하거나 실제 모델의 새 세션에서 동작을 평가한 결과는 아니다. 사용자 설치본은 **0.1.11**로 유지했다.

실제 Codex CLI 목록에서 **5,451개** 후보를 발견했으며 그중 현재 기본 정책에 허용된 후보는 **65개**였다. 수치는 조회 시점의 로컬·호스트 목록에 따라 변한다. 이 수치는 설치·인증 완료나 모든 후보의 유용성을 뜻하지 않는다.

이미 등록된 공개 `contextual-capabilities` Git 출처를 별도 임시 디렉터리에 가져와 목록 검증에 성공했다. 원격 커밋은 `4fc09de555adb1168bc3d6a484f45f9ca9fc1a8d`이며, 실제 사용자 마켓플레이스 체크아웃은 갱신하지 않았다. 사용자 Codex 설정·훅 설정, Claude 설치·등록 파일, 기존 Codex 관리자 캐시의 파일 해시는 검사 전후 같았다.

## 재현

```bash
python3 -m unittest discover -s tests -v
python3 scripts/verify_catalog_refresh.py --output /private/tmp/catalog-refresh-report.json
```

실제 등록된 Codex 목록을 읽으려면 `--live-codex`를 추가한다. 이미 등록된 공개 관리자 Git 출처의 네트워크 검증에는 `--live-git`를 추가한다. 기본 실행은 격리된 시험 CLI와 데이터로 검증하며 사용자 설치·설정을 바꾸지 않는다. `--live-git`는 로컬 Claude 등록 파일의 공개 관리자 출처가 있어야 실행된다.

## 설치·정리

- 새 스킬·플러그인·커넥터의 native 설치 또는 제거: **0개**.
- 실제 관리자 설치본·기존 신뢰 훅: 변경 없음.
- 시험용 패키지·DB·원격 스냅샷·MCP 프로세스: 종료 후 임시 디렉터리 제거 확인.
- 스킬 검증에만 사용한 PyYAML: 임시 가상환경에 설치해 `quick_validate.py`를 실행한 뒤 환경 전체 제거. 제품 런타임 의존성 추가 없음.

## 남은 경계

원격 동기화는 등록된 HTTPS Git 마켓플레이스에 한정한다. SSH Git·JSON URL·전체 외부 서비스 목록을 직접 동기화하지 않는다. native 원격 참조는 메타데이터로 발견하므로 계정 인증이나 플랫폼 설치가 필요한 후보를 바로 실행할 수 없다. 기존 설치 스킬·플러그인은 호스트가 직접 노출하는 기능을 사용한다. 목록·정책 갱신이 실제 작업의 선택 정확도를 높였는지는 별도의 실사용 라벨과 새 모델 세션 평가가 필요하다.
