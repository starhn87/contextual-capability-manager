# 배포와 실제 설치본 검증 — 0.1.11, 2026-10-04

Codex와 Claude Code의 관리자 플러그인을 모두 **0.1.11**로 업데이트했습니다. Codex의 일반 답변은 기존 신뢰된 훅을 켜거나 끈 경우 모두 추가 능력 0개를 표시했고, 훅 없는 정적 지침 조회는 승인 거부 없이 스킬 행과 조회 범위를 표시했습니다. Claude는 0개 표시와 스킬 준비·결과 기록·권한 해제 흐름을 확인했습니다.

이 보고서는 [0.1.10 소스 검증](codex-hook-free-2026-10-04-0.1.10.md)의 후속입니다. 최종 시험은 프로젝트에 포함 스킬을 복사하거나 소스 MCP를 등록하지 않고 **실제 설치된 패키지**를 새 CLI 세션에서 실행했습니다. 코드 커밋은 `a75f315`이며, 앞선 읽기 경로 구현 커밋 `bb1f169`도 푸시했습니다.

## 설치본에서 발견한 문제와 수정

0.1.10 설치 후 기존 Codex 사용자 훅을 켠 일반 요청은 필요 없는 `release_capability_session`을 호출했습니다. CLI의 기본 비대화형 승인 정책이 이를 거부했고, 답변에 0개 영수증이 빠졌습니다. 종료 훅은 별도로 정상 정리했습니다. 이 실패를 성공으로 바꾸거나 기록에서 삭제하지 않았습니다.

0.1.11은 포함 스킬·MCP 초기화 안내·해제 도구 설명에 **세션 연결과 프롬프트 관찰은 능력 준비·활성화가 아님**을 명시합니다. 세션 ID를 받았다는 이유만으로 해제를 호출하지 않습니다. 실제 준비·재활성화 뒤에는 기존 정리를 유지하고, 이전 접근이 불확실할 때는 먼저 읽기 전용 세션 요약을 확인합니다. 훅 코드나 도구 승인 정책을 바꾸지 않았습니다.

Codex 스킬 시험은 설치본의 기본 카탈로그에 포함된 로컬 `Note summarizer`를 사용했습니다. `read_static_skill` 한 번만 호출해 받은 지침과 실제 답변의 결정·민수·10월 6일·미해결 출시일을 대조했습니다. 신규 준비·결과 기록·해제 호출은 없었습니다. 읽기 요약은 전체 세션의 설치나 기존 권한 정리를 증명하는 영수증으로 취급하지 않습니다.

Claude 스킬 시험은 임시 카탈로그·정책·저장소를 사용했습니다. 대상 파일에만 넣은 검증 태그가 답변에 나타났고, `resolve_static_skill → record_capability_result → release_capability_session` 호출과 저장된 영수증 수치가 일치했습니다. 이 실행에만 기존 8개 도구를 정확한 이름으로 허용했으며 전역 승인을 추가하지 않았습니다. 일반 요청은 이 허용 목록 없이 실행했습니다. 따라서 Claude의 준비·해제 성공을 기본 무승인 실행의 증거로 해석하지 않습니다.

Codex 스킬 답변은 제목을 생략하고 조회 범위 문구를 바꿨습니다. 원본의 제목·일부 단어 검사값은 false로 보존하고, 실제 스킬 행·수치·이번 조회만 다룬다는 의미를 따로 확인했습니다. 형식이나 동일한 제목을 모든 요청에서 강제하는 UI 구현은 아닙니다.

## 기존 훅 신뢰 보존

`codex plugin add contextual-capability-manager@local-capabilities --json`으로 기존 플러그인을 갱신할 수 있었습니다. 다만 이 CLI는 구버전 캐시를 삭제했습니다. 사용자의 세 훅은 0.1.8 캐시 경로를 참조하므로 그대로 두면 다음 실행에서 파일을 찾지 못합니다.

업데이트 전 저장한 파일 해시와 일치하는 원본 36개 파일을 복원했고, 다음 갱신에서는 검증한 원본 백업으로 같은 파일만 복원했습니다. **신뢰한 0.1.8 경로에 새 코드나 가변 실행기를 넣지 않았습니다.** 설치 등록과 MCP·포함 스킬은 0.1.11을 사용하며, 기존 사용자 훅의 실행 코드와 기록 버전은 0.1.8입니다. 두 버전이 같은 기존 저장소를 사용하는 조건을 구분해 검증했습니다.

`hooks/list`에서 기존 SessionStart·UserPromptSubmit·SessionEnd가 모두 활성·신뢰 상태임을 확인했습니다. `~/.codex/hooks.json`과 `config.toml`은 작업 전후 해시가 같고, 신뢰 기록을 직접 편집하거나 우회 옵션을 사용하지 않았습니다. 훅 정의를 바꾸는 향후 업데이트에는 플랫폼의 정상 재검토가 필요합니다. [공식 훅 신뢰 안내](https://learn.chatgpt.com/docs/hooks).

## 검증 범위와 사용 방법

전체 단위·통합 테스트 76개가 통과했습니다(3.880초). 플러그인·마켓플레이스 manifest를 native Claude CLI로 검증했습니다. 양쪽 설치본의 패키지 37개 파일과 포함 스킬 해시가 빌드·소스와 일치합니다. 최종 포함 스킬 SHA-256은 `33b647d1bdbd9d34817637f59c482054038005a939ecdde898ff3e392f69d645`입니다.

현재 사용자는 앱·CLI의 기존 프로세스를 다시 시작하고 새 세션을 열면 됩니다. 이미 신뢰한 훅 정의를 변경하지 않았으므로 이번 적용에 추가 `/hooks` 조작을 요구하지 않습니다. 처음 설치하는 사용자는 승인된 로컬·기존 캐시 정적 지침 조회와 0개 요약에 훅 신뢰가 필요 없습니다. 전체 프롬프트 관찰·종료 훅 정리를 쓰려면 별도 훅 검토가 남아 있습니다. CLI의 훅 영구 일괄 신뢰 명령이 생겼다는 의미는 아닙니다.

원격 다운로드·실행형 도구·새 외부 계정 인증은 정상 플랫폼 승인을 따라야 합니다. 훅 없는 관리자 세션 핸들과 게이트웨이 연결 소유 권한 정리는 [후속 설계](codex-installation-friction-2026-10-04.md)에 남아 있습니다. 이 합성 시험은 모든 작업의 표시 일관성, 실사용 정확도, 답변 품질·시간 절감을 증명하지 않습니다. 데스크톱의 현재 열린 대화에 즉시 재로딩됐다는 확인도 아니며, 이번 동작 증거는 새 CLI 세션입니다.

초기 0.1.10 Codex 스킬 시험은 임시 fixture 카탈로그가 설치 MCP에 전달되지 않아 검증 태그가 없었습니다. 실제 응답은 기본 `Note summarizer`를 정상 적용했고, 후속 시험은 이 기본 카탈로그를 명시적으로 사용했습니다. 태그 검사 실패와 누락된 임시 DB 결과도 원본에 보존합니다. 로컬 집계 `native-0.1.10-deployment/report-0.1.11.json`은 초기 실행과 최종 5건의 조건·의미 검증을 구분합니다.
